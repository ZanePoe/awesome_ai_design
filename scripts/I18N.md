# i18n layout

Every catalogue ships the same reading surface in five languages: English (default, repo root), Simplified Chinese, Spanish, Hindi and French (top five languages by total speakers).

## Output tree

| Path | Content |
| --- | --- |
| `README.md`, `docs/projects.md`, `docs/rankings.md`, `docs/<static>.md`, `CONTRIBUTING.md` | English (default) |
| `locales/<lang>/README.md`, `locales/<lang>/docs/projects.md`, `locales/<lang>/docs/rankings.md`, `locales/<lang>/docs/<static>.md`, `locales/<lang>/CONTRIBUTING.md` | one mirror per locale in `zh`, `es`, `hi`, `fr` |

The static prose of this catalogue is `docs/readme-intro.md`, `docs/selection.md`, `docs/methodology.md`, `docs/research.md` and `CONTRIBUTING.md` — `build.STATIC` lists exactly those five, and `validate()` requires both the English original and one copy per mirrored locale.

`locales/<lang>` mirrors the root layout, so relative links inside a mirror (`docs/projects.md`, `CONTRIBUTING.md`) are written once in the templates. Generated files sit one level down in a mirror, so links they build into the repository root (`LICENSE`, `research/README.md`) use the `{R}` prefix: `""` in English, `"../../"` from `locales/<lang>/README.md`.

Hand-written prose resolves from its own directory, which is one level deeper, so the counts differ — `check_links()` enforces this:

| File | Link into repository root |
| --- | --- |
| `docs/research.md` (English) | `../research/…` |
| `locales/<lang>/docs/research.md` | `../../../research/…` |
| `CONTRIBUTING.md` (English) | `data/projects.json`, `record/` |
| `locales/<lang>/CONTRIBUTING.md` | `../../data/projects.json`, `../../record/` |

`build.INLINE` (`docs/readme-intro.md`, `docs/selection.md`) lists the two prose files that are embedded into the README body: the intro supplies the opening block, and `docs/selection.md` is the whole "如何选择" section (its own `##` heading included, unlike the other catalogues that keep that paragraph in `templates.choose`). Both therefore resolve their relative links from the locale root, writing `docs/projects.md` and `CONTRIBUTING.md` in both layouts.

Language switcher: the generated README of every locale starts with the same line linking all five.

Category navigation: right after the intro the README carries a `## <sections.tags>` heading whose single line links all eight categories, `· ` separated, in `categories` key order, to their `###` headings via `build.anchor()` — the `github-slugger` rule (lowercase, drop ASCII punctuation and U+2000-206F/U+2E00-2E7F, spaces to hyphens), so punctuation such as the `、` in a Chinese category label stays part of the anchor.

## Source of truth

| File | Role |
| --- | --- |
| `data/projects.json` | canonical review data, written in Chinese; also the fallback for `zh` |
| `locales/<lang>/ui.json` | `language`, `language_name`, `list_separator` plus category, scope, licence-status, tier, mode labels, table headers, section titles and paragraph templates |
| `locales/<lang>/entries.json` | `repo → {description, boundary, license_label, license_note}` for that language, plus an optional `name` |
| `locales/<lang>/docs/*.md`, `locales/<lang>/CONTRIBUTING.md` | hand-written static prose per locale |
| `locales/zh/ui.json` | the Chinese strings `build.py` used to hard-code; it is the translation source for every other locale |

`zh` has no `entries.json` — `build.py` falls back to `data/projects.json`. Every other locale must provide one entry per repository, or `validate()` fails.

Display names: `data/projects.json` keeps one canonical `name` per repository and is never edited for i18n reasons. Five of them carry characters outside the Latin range (`figma/mcp-server-guide`, `superdesigndev/superdesign`, `penpot/penpot-mcp`, `open-pencil/open-pencil`, `ZSeven-W/openpencil`), and `build.CJK` — Han plus CJK/fullwidth punctuation — is the gate: `render()` prints `entries()[repo]['name']`, so every non-`zh` locale has to ship a `name` for exactly those repos; `validate()` rejects the missing ones with `missing localized display name for <locale> <repo>`, and the wording (e.g. `OpenPencil (desktop)`) is decided from the official README by the translation, not here. `data/rankings.csv` always writes the canonical name, and `category`, `scope` and `license_status` stay code-valued, so the CSV is language-neutral — it publishes `maintenance_tier` (0-3), never the localized tier label.

## Translation rules

- Keep facts identical to the Chinese source. Do not add claims, benchmarks or guarantees.
- Leave unchanged: repository names, project names, URLs, file paths, commit SHAs, license identifiers (MIT, Apache-2.0, MPL-2.0, AGPL-3.0 …), star counts, dates, model names, code blocks, Markdown table shape.
- Literal search keywords inside `docs/research.md` stay verbatim; only the surrounding prose and table headers are translated. That file is the one exception to the no-Chinese rule for non-`zh` locales, and `tests/test_i18n.py` enforces the narrow form of the exception: Chinese may appear only in Markdown table rows or inside backticks, never in prose lines.
- `research/` (`research/README.md`, `research/baseline.md`, the discovery log) is the audit trail of this catalogue and is never translated, so it is not part of `STATIC`; the README of every locale links to it through `{R}`. This repository has no `record/` directory yet — `templates.records_note` therefore names it in backticks instead of linking to a missing path, and the same wording applies once change records start landing there in the language used at verification time.
- `data/rankings.csv`, `data/metrics.json` and every `README.md`/`docs/projects.md`/`docs/rankings.md` in any locale are generated: run `python scripts/build.py`, never hand-edit them.

## Per-locale checklist

`locales/<lang>/` for `en` (root) plus `es`, `hi`, `fr` mirrors, each needing:

| File | Must contain |
| --- | --- |
| `ui.json` | top-level keys `language`, `language_name`, `list_separator`, `categories`, `scopes`, `license_status`, `modes`, `tiers`, `tags`, `headers`, `sections`, `templates` — nothing else; `language` equals the locale code, `list_separator` is `, ` (`、` in `zh`), and `language_name` is the language's own name |
| `ui.json → categories` | the 8 keys `studios`, `canvas`, `skills`, `design_systems`, `bridges`, `diagrams`, `research`, `historical`; `scopes`: `core`, `adjacent`, `research`, `historical`, `restricted`; `license_status`: `verified`, `custom`, `source_available`, `unverified`; `modes`: `balanced`, `stars`, `activity`, `recent`; `tags`: `baseline`, `archived`, `license`; `headers`: `shortlist`, `categories`, `detail`, `rankings`; `sections`: `current`, `shortlist`, `tags`, `toc`, `data`, `thanks`, `detail_title`, `rankings_title`; `tiers` is 4 strings in tier order |
| `ui.json → templates` | exactly `current`, `shortlist_note`, `toc_note`, `detail_intro`, `rankings_intro`, `entry`, `source_link`, `data`, `thanks`, `records_note`, each keeping the placeholder set of the `zh` string (`{total} {baseline} {added} {reviewed} {as_of}`, `{category} {scope} {boundary} {maintenance} {commits_30d} {commits_90d} {license} {license_source} {license_status} {license_note} {reviewed_at} {sources}`, `{index}`, `{R}`); no other placeholder names |
| `entries.json` | one object per repository key of `data/projects.json` with `description`, `boundary`, `license_label`, `license_note`, plus a `CJK`-free `name` for the five display names listed above |
| `docs/readme-intro.md`, `docs/selection.md`, `docs/methodology.md`, `docs/research.md`, `CONTRIBUTING.md` | translated prose; keep the `##` heading of `docs/selection.md` because the whole file becomes the README's selection section |

Missing or divergent files fail `python scripts/build.py --check` and `python -m unittest discover -s tests -v`.
